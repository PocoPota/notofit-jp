# グリフ単位の垂直調整

計画書の工程④。特定のグリフだけを上下に動かす。計画書は [plan.md](plan.md)。

---

## 1. なぜ必要か

**Outfit のコロン類は、和文の全角コロンと並ぶと明らかに低い位置にある。** 合成後の
フォントで字面の中心を測ったもの（wght=400、1000 upem 単位）。

| 欧文 | 中心 | 和文相当 | 中心 | 差 |
| ---- | ---- | -------- | ---- | -- |
| `:` | 212 | `：` | 374 | **−162** |
| `;` | 148 | `；` | 296 | −148 |
| `(` `)` | 311 | `（` `）` | 380 | −69 |

参考として、欧文自身の x-height の中心は 238、cap-height（`B`）の中心は 347。
つまり `:` は**自身の x-height 中心からも 26 下**にある。

**CSS では直せない。** `vertical-align` や `translateY` は要素単位でしか作用せず、文中の
特定のグリフだけを動かす手段がない。フォント側で動かすしかない。

## 2. 何に合わせるのか

**答えは1つに決まらない。** 上の数値が示すとおり、候補が複数ある。

| 合わせ先 | `:` の移動量 | 考え方 |
| -------- | ------------ | ------ |
| 調整なし | 0 | Outfit の設計をそのまま尊重する |
| 欧文の x-height 中心 | +26 | 欧文組版として自然な位置に正す |
| 和文 `：` の中心 | +163 | 和文と混植したときに高さを揃える |

欧文だけの文脈（`12:34`）では x-height 中心が自然に見え、和文と混植する文脈
（`日本語：英語`）では和文に寄せたくなる。**どちらを重視するかは目視で決める**ため、
調整ツールで両方の基準線を出しながら判断する。

## 3. 調整ツール

```bash
.venv/bin/python -m notofit.server   # http://127.0.0.1:8765/glyphs
```

和欧調整ツール（[tuner.md](tuner.md)）とは別のページ。扱う値の性質が違うため分けている。
和欧の関係は連続量をスライダーで往復させて詰めるが、こちらは**対象グリフを選び、
基準線に合わせる**という別種の作業になる。

### 画面

- **対象グリフ** — 候補を一覧から選ぶ。任意の文字を追加できる。各ボタンに現在の移動量を
  表示し、調整済みかどうかが一目で分かる
- **移動量** — スライダーと、「x-height の中心に合わせる」「和文 `：` の中心に合わせる」
  「0 に戻す」のワンクリック指定。**移動量は実測から計算して表示される**ので、
  数値を自分で出す必要がない
- **基準線** — 見本にベースライン・欧文の x-height 中心・和文相当の中心を重ねる。
  ベースラインの位置は、字面に埋めた目印の位置を実測して求めている
- **調整前の重ね表示** — 調整後を前面、調整前を背面に置く。動いていないグリフは前面が
  覆い隠すため、**動いた箇所だけが赤くはみ出して見える**
- **文脈** — `A:B` `12:34` `あ:い` と、本文16px での見え方

### 保存

`config/glyph-shifts.json` に保存する。和欧調整ツールとは別ファイルにしてあり、
互いの保存で上書きし合わない。

```jsonc
{
  "weights": {
    "400": { ":": 26 },   // 文字 -> 移動量（1000 upem 単位、正で上）
    "700": { ":": 24 }
  }
}
```

**ウェイトごとに値を持つ。** 細いウェイトと太いウェイトではドットの見え方が変わるため、
最適値が異なりうる（計画書の R4）。

## 4. 実装

`notofit/glyphshift.py`。検証は `tests/test_glyphshift.py`。

対象グリフのアウトラインを垂直に平行移動するだけで、**`hmtx` は触らない**。垂直方向の
移動は字送りに影響しないため。

**合成（工程③）の後に適用する。** 合成前に欧文へ適用しても結果は同じだが、合成後なら
和文と並べた状態で確認しながら決められる。また静的化後であるため、ウェイトごとに別の値を
持てる。

### 本番ビルドへの接続

`build_weight(..., shifts=...)` で渡す。**現時点では本番ビルドの入口自体が存在しない**
ため、`config/glyph-shifts.json` を読んで渡す処理はまだ書かれていない。工程⑤⑥とあわせて
M3 で用意する。

## 5. 決めること

- 対象とするグリフ（既定の候補は `:` `;` `(` `)` `?` `!` などの約物・記号）
- 各グリフの移動量、および何に合わせるか（→ 2）
- ウェイトごとに変えるか、全ウェイトで同じ値にするか
