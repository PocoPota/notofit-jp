# Noto Sans JP の palt はウェイトで変わる

調査日: 2026-07-27
関連: 計画書 [../plan.md](../plan.md) の R3、工程②

---

## 事実

Noto Sans JP の `GPOS` には `FeatureVariations` があり、**`wght` がある値を超えると
`palt` に lookup が1つ追加される**。

| wght | palt の lookup | 対象グリフ数 |
| ---- | -------------- | ------------ |
| 400  | `[6]`          | 328          |
| 700  | `[6, 10]`      | 332          |
| 900  | `[6, 10]`      | 332          |

条件は正規化座標で 0.779〜1.0。**700 はすでにこの範囲に入る**（avar により正規化が
非線形なため、単純比例で計算すると境界を 723 と読み違える）。本プロジェクトの対象で
ある 400 / 700 がまたいでいる。

## 影響は小さい

`XAdvance` は両ウェイトとも約物すべて −500 で同一。差が出るのは `XPlacement` の数値と、
カバレッジ4グリフ分のみ。

| 文字 | wght=400 (XAdv, XPlace) | wght=700       |
| ---- | ----------------------- | -------------- |
| 、   | (−500, −9)              | (−500, −3)     |
| 「   | (−500, −481)            | (−500, −485)   |
| （   | (−500, −464)            | (−500, −456)   |
| ・   | (−500, −250)            | (−500, −250)   |

**幅は変わらないため、R3 が懸念していた「太いウェイトで急に詰まる」は 400 / 700 の
範囲では起きない。** 差は重いウェイト向けに約物の位置を微調整したものと読める。

将来 800 / 900 を追加する場合も lookup 構成は 700 と同じであり、新たな段差は生じない。

## 実装への反映

**`palt` の焼き込みは静的インスタンス化した後に行う。** 可変フォントのまま焼き込むと、
どのウェイトの `palt` を焼いたのかが曖昧になるため。`instantiateVariableFont` を通すと
`FeatureVariations` は解決され、そのウェイトの lookup 構成が確定する。

また焼き込み処理は、`palt` にぶら下がる**すべての lookup を辿って合計をとる**必要がある。
シェイピング時は複数の lookup が累積して適用されるため、lookup 6 だけを見ると 700 で
値がずれる。

実装は `notofit/palt.py`、検証は `tests/test_palt.py`。
