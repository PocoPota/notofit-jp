# 和欧調整ツール 仕様

Notofit JP の設計値を目視で決めるための開発支援ツール（GUI）の仕様。
配布物ではなく、M2（設計値の確定）のための道具である。

計画書は [plan.md](plan.md)。

---

## 1. 目的

`SCALE` / `BASELINE_OFFSET` / ウェイトの組み合わせは、単体では正解が存在せず、和文と
欧文を並べて初めて「高い / 低い / 細い」が判断できる。しかも3つが相互に影響する
（欧文を拡大すれば太く見えるため `wght` を戻したくなる）。約物の隣接時の詰め量も同様に、
組んだ状態を見なければ決まらない。

この往復を目視で行うための調整器とする。

## 2. 位置づけ

**成果物は設定値（JSON）であり、フォントそのものではない。**

```
和欧調整ツール ──> 設定 JSON ──> ビルドスクリプト ──> dist/
   （値を決める）              （配布物を作る）
```

ツールが出力した値を合成ツールの config に流し込む形とし、責務を重ねない。ツールを
経由しなくてもビルドは回る状態を保つ。

## 3. 担当範囲

**原則: 目視でしか決められない値を扱う。数値的な制約が判断を支配する値は扱わない。**

前者は組んだ状態を見て初めて良し悪しが決まる連続量で、スライダーを往復させる作業になる。
後者は「置き換え互換性への影響がどれだけか」といった数値で決まり、目視は最後の確認に
すぎない。連続スライダーにすると制約を見失いやすいため、**表示条件のプリセット**として
扱う（→ 4）。

### 範囲内

| パラメータ           | 内容                                       |
| -------------------- | ------------------------------------------ |
| `SCALE`              | 欧文の拡縮                                 |
| `BASELINE_OFFSET`    | 欧文の上下位置                             |
| 和文 / 欧文の `wght` | 見かけの太さを揃える組み合わせ             |
| 約物の `kern`（`pair` / `middle`） | 約物が隣接したときに引く量 |

`SCALE` / `BASELINE_OFFSET` / `wght` は **出力ウェイトごとに個別の値を持つ**。当面は
400 / 700 の2ウェイトだが、将来の追加が差分で済むよう、設定は最初からウェイトごとの
配列とする。

約物の `kern` は、クラス行列の構造（どのクラスの組にどちらの値を当てるか）を固定し、
**括弧・句読点どうし（`pair`）と中点がらみ（`middle`）の2つの量だけ**を調整対象とする。
行列そのものは JLREQ から導かれるものであり、目視で動かす対象ではない
（→ [yakumono.md](yakumono.md)）。

### 範囲外

| 項目                       | 理由                                                                 |
| -------------------------- | -------------------------------------------------------------------- |
| グリフ個別の垂直調整（④）  | 対象が数十グリフあり、別種の UI が必要。混植の全体調整とは作業が異なる |
| `palt` の焼き込み比率      | 置き換え互換性への影響という数値が判断を支配する（→ 4）                |
| `excludeCodepoints`        | 記号ごとの字形の好みを一覧で選ぶ作業。混植プレビューと無関係           |
| サブセット化・CSS 生成・配布 | ビルドの責務                                                          |

## 4. `palt` 焼き込み比率の扱い

**調整対象ではなく、プレビューの表示条件とする。**

この値の決め手は R5 のトレードオフ（焼き込むほど字面は締まるが、既存サイトのレイアウト
差分が大きくなる）であり、**「どれだけ字送りが変わるか」という数値**が支配的である。
目視は最後の確認にすぎない。

ただし比率によって和文の見え方は変わるため、プレビューには反映されている必要がある。
**カテゴリごとのプリセット切り替え**（0 / 0.5 / 1.0）とし、どの前提で見ているかを常に
明示する。

| カテゴリ    | 既定 | 内容                                     |
| ----------- | ---- | ---------------------------------------- |
| かな        | 1.0  | プロポーショナル化する                    |
| 全角英数    | 1.0  | 同上                                      |
| 約物        | 0.0  | 全角のまま。隣接処理は `kern` が担う（→ 3）|

## 5. プレビューの固定条件

調整対象ではないが、本番と同じ条件で見るために固定するもの。

| 条件                      | 値                                                      |
| ------------------------- | ------------------------------------------------------- |
| `text-autospace`          | `normal`（常時オン）                                    |
| 書字方向                  | 横書きのみ                                              |
| `palt` 焼き込み比率       | プリセットから選択（→ 4）                                |

`text-autospace` をオフの状態で `BASELINE_OFFSET` を詰めると、本番と違うものを見て
判断することになる。

## 6. 実装

**ローカルサーバ + ブラウザ**の構成とする。フォント生成は Python 側（`notofit.build`）が
担い、ブラウザは表示のみを行う。本番ビルドと同じコードを通すことで、2. の「調整画面で
見たものと配布物が食い違わない」を担保する。

```
tuner/index.html   GUI（単一ファイル）
notofit/server.py  ローカルサーバ
notofit/build.py   ビルドコア（プレビューと本番で共用）
notofit/palt.py    palt の焼き込み
config/tuning.json 調整結果
```

### 起動

```bash
.venv/bin/python -m notofit.server   # http://127.0.0.1:8765/
```

### プレビューの生成経路

サンプル文章に出てくる文字だけへサブセットしてから静的化・合成する。フル合成は約8秒
かかるが、この経路なら**パラメータ変更あたり 0.03〜0.3 秒**で、スライダー操作に追従する。
工程⑤のサブセット化を前倒しで使っているだけで、本番と別の処理をしているわけではない。

中間生成物は `build/cache/` にキャッシュする。`palt` 比率とサンプル文章が変わったときだけ
和文側を作り直す。

### 比較表示

素の Noto Sans JP を同時に生成し、2通りで比較できる。

- **並べる** — 上下に並べて字面と太さを見る
- **重ねる** — 素の Noto を赤で重ねる。折り返しでズレると比較にならないため `nowrap` とし、
  **字送りの差が横方向のズレとして蓄積して見える**。置き換え互換性の確認そのものになる

約物の見本はペアごとに独立した要素として並べ、間隔は CSS で一定にする。文字列を空白で
区切ると、区切りの見た目の幅が前後の約物のインク位置に左右されて比較にならないため。

素の Noto は `text-spacing-trim: space-all` で既定のトリムを無効化し、全角ベタ
（Safari / Firefox で見える状態）を基準として表示する。チェックボックスでトリムありの
状態（Chromium 相当）にも切り替えられる。

## 7. 残っている検討事項

- サンプル文章の追い込み（現在は汎用的な混植文・約物・数字）
- `dist/` を対象にした本番プレビュー（現在はサブセット版のみ）
