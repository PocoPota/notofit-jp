# 字幅のプロポーショナル化

Notofit JP における、かな・全角英数の字幅の扱い。約物の扱いは
[yakumono.md](yakumono.md)、計画書は [plan.md](plan.md)。

---

## 1. 何を決めるのか

和文は原則すべての文字が全角（1em）を占める。このうち**かなと全角英数を、字面に応じた
幅に変える**（＝プロポーショナル化する）かどうかが論点である。Noto Sans JP が持つ
`palt` の調整量を、フォントの既定の字幅に恒久的に書き込むかどうかの判断になる。

問いは2つに分かれ、**片方は確定していて、もう片方は M2 で決める。**

| 問い | 状態 |
| ---- | ---- |
| **プロポーショナル化するか** | **未確定。M2 で決める**（→ 7） |
| するとして、どこまで焼き込むか | **確定。全量（比率 1.0）**。中間の値は意味を持たない（→ 7） |

対象ごとの扱い。かな・全角英数の値は**現時点の既定であり、M2 で確定する**。

| 対象 | 比率 | 状態 |
| ---- | ---- | ---- |
| かな（ひらがな・カタカナ） | 1.0 | 既定値。M2 で 1.0 / 0.0 を確定 |
| 全角英数（`Ａ` `１`） | 1.0 | 同上 |
| 約物 | **0.0** | 確定。全角のまま。隣接時の処理は `kern` が担う（→ [yakumono.md](yakumono.md)） |
| 漢字 | — | `palt` の対象外。もともと変わらない |

## 2. `palt` とは

OpenType の feature（機能）のひとつで、**全角固定の字幅を字面に応じた幅に詰める**もの。
名前は proportional alternate widths の略。

詰め幅は文字ごとに異なり、字面が小さいものほど大きく詰まる。

| 文字 | 全角時 | `palt` の調整量 | 結果 |
| ---- | ------ | --------------- | ---- |
| `あ` | 1000 | −29 | 971 |
| `ア` | 1000 | −69 | 931 |
| `Ａ` | 1000 | −224 | 776 |
| `。` | 1000 | −500 | 500 |

調整量は2つの値の組で、**`XAdvance`** が字幅（次の文字までの送り量）、**`XPlacement`**
が字面そのものの水平移動量。幅だけ縮めると字面が枠の中で右に寄ってしまうため、両方を
組で扱う。

Noto Sans JP で `palt` が調整量を持つのは **328グリフ**。

| 分類 | グリフ数 | 本プロジェクトの扱い |
| ---- | -------- | -------------------- |
| かな | 195 | 焼き込む |
| 全角英数 | 60 | 焼き込む |
| 約物 | 45 | 焼き込まない |
| その他（記号・異体字など） | 28 | 焼き込まない（→ 6 の既知の限界） |

## 3. なぜ焼き込むのか

`palt` は CSS の `font-feature-settings: "palt"` で有効にできるが、**指定したページと
しないページで結果が変わる**。フォントの既定の字幅に書き込んでしまえば、CSS を書かなくても
どのブラウザでも同じ結果になる。計画書の方針4（調整はフォント側に焼き込み、CSS に依存
しない）に沿う。

**プロポーショナル化するなら比率は 1.0**（全量を焼き込む）になる。中間の値では
`palt` に残りが出るため（→ 7）。

なお焼き込みののち、**`palt` の feature 自体を削除する**。約物には焼き込まないため値が
残り、CSS で指定されると約物が潰れるため（→ [yakumono.md](yakumono.md)）。結果として、
比率を 0.0 にした場合も `palt` は使えなくなる。字幅を決めるのはフォントの側である、
という立場を取る帰結である。

## 4. なぜ約物と分けるのか

`palt` の対象は約物も含むが、**約物には焼き込まない**。

`palt` は文脈を見ずに、対象の文字を常に同じだけ詰める。約物に適用すると、`」「` のように
隣接して詰めたい場合だけでなく、`あ「い` のように単独で現れる場合まで詰まってしまう。
JLREQ では単独の約物は全角が正しいため、これは詰まりすぎになる。

約物は全角のまま残し、隣接したときだけ `kern` のペア調整でアキを取り除く。詳細と、
一律焼き込みを不採用にした経緯は [yakumono.md](yakumono.md)。

かなや全角英数にはこの問題がない。前後の文字によらず一定の幅で構わないため、単純な
焼き込みで足りる。

## 5. 置き換え互換性への影響

**プロポーショナル化すると字送りが変わる。** `あいうえお` の5文字は全角なら 5.000em、
焼き込み後は 4.610em（wght=400）。既存サイトを差し替えると、日本語主体のページでは行の
折り返し位置が変わる。計画書の R5 にあたり、**これを許容するかどうかが M2 の判断そのもの**
である。

判断材料として、次の2点は影響しないことが分かっている。

- **体感のフォントサイズは変わらない。** 字面そのものの大きさは変えず、余白だけを詰める
  ため、文字が小さくなったようには見えない
- **行の高さは変わらない。** 縦メトリクスは Noto Sans JP のまま固定している（工程③）

変わるのは折り返し位置だけ、ということになる。その量は7章で測る。M2 で方針を決め、
M4（置き換え互換性の確認）で実際のページに当てて確かめる。

## 6. 実装

`notofit/palt.py`。検証は `tests/test_palt.py`。

### カテゴリの判定

グリフの符号位置から分類する。

| カテゴリ | 符号位置 |
| -------- | -------- |
| かな | U+3041–3096、U+309D–309F、U+30A1–30FA、U+30FC–30FF、U+31F0–31FF |
| 全角英数 | U+FF10–FF19、U+FF21–FF3A、U+FF41–FF5A |
| 約物 | U+3000–303F、**U+30FB**、U+FF01–FF0F、U+FF1A–FF20、U+FF3B–FF40、U+FF5B–FF65、U+2018–201F |
| その他 | 上記以外 |

**`・`（U+30FB）はカタカナのブロックにあるが約物として扱う。** かなに含めると焼き込まれて
半角になってしまう。

### 守るべき制約

- **静的インスタンス化した後に焼き込む**
- **`palt` にぶら下がる lookup をすべてたどって合計する**

いずれも `palt` の中身がウェイトによって入れ替わるため。理由と実測は
[notes/palt-weight-boundary.md](notes/palt-weight-boundary.md)。

### 既知の限界

**符号位置を持たないグリフは焼き込まれない。** `palt` の対象328グリフのうち23は cmap に
載っておらず、GSUB 経由でのみ現れる。符号位置から分類する方式では「その他」となり、
比率 0.0 が適用される。

内訳を追うと、かなと結合用の濁点・半濁点（U+3099 / U+309A）が `ccmp` で合成された
グリフだった（`あ`＋`゙`、`ン`＋`゙`、`ㇷ`＋`゚` など）。**`ccmp` は既定で適用されるため、
本文中に現れうる。** その場合、周囲のかなが詰まっているなかでこれらだけ全角のまま残る。

通常の日本語は合成済みの符号位置（`が` U+304C など）を使うため影響はごく小さいが、
分類の穴ではある。GSUB の置換関係を逆に辿って元グリフの分類を継承させれば解消できる。

同様に、全角の記号（`￥` U+FFE5 など）も「その他」に落ちて焼き込まれない。全角数字が
詰まるなかで `￥` だけ全角のまま残ることになる。

## 7. 比率をどう決めるか

### 実質は 1.0 か 0.0 の2択

比率は 0.0〜1.0 の連続値を指定できるが、**中間の値には意味がない。**

焼き込まなかったぶんは `palt` に残るため、CSS で `palt` を指定したページでは追加で詰まる。
つまり**中間値は「指定の有無で見た目が変わる」状態を残したまま、Noto Sans JP とも違う
字送りになる**。いいとこ取りにはならない。

`あいうえお` の実測。

| 比率 | 既定の字送り | CSS で `palt` を指定したとき |
| ---- | ------------ | ---------------------------- |
| 0.0 | 5.000em | 4.610em（指定で変わる） |
| 0.5 | 4.806em | 4.612em（指定で変わる） |
| **1.0** | **4.610em** | **4.610em（指定しても変わらない）** |

**1.0 のときだけ `palt` に何も残らず、CSS の指定に左右されなくなる。** 計画書の方針4
（フォント側に焼き込み、CSS に依存しない）を満たすのはこの値だけである。

0.0 は「何もしない」選択肢として成立する。字送りは Noto Sans JP と完全に一致し、`palt` の
挙動も Noto のままなので、置き換えとしては最も安全になる。

したがって選択は次の2つに絞られる。

| 比率 | 得られるもの | 引き換えに失うもの |
| ---- | ------------ | ------------------ |
| **1.0** | 字面が締まる。CSS の指定に左右されない | 字送りが変わる（本文で −4.5%） |
| **0.0** | 字送りが Noto Sans JP と完全一致 | 全角ベタのまま。CSS 指定で変わる余地が残る |

**既定は 1.0 としている**が、これは確定ではない。M2 で決めるべきは「字送りが 4.5% 変わる
ことを受け入れるか」の一点に尽きる。受け入れないなら 0.0 に落とす。

### どれだけ変わるかを測る

代表的な本文（135字）で比率ごとの総送り量を Noto Sans JP と比べたもの。

| 比率 | 総送り量 | Noto 比 |
| ---- | -------- | ------- |
| 0.00 | 128.585em | 100.0% |
| 0.50 | 125.712em | 97.8% |
| 1.00 | 122.840em | **95.5%** |

比率 1.0 では日本語主体の本文が **4.5% 短くなる**。1行40字なら 1〜2字ぶん多く入る計算で、
段落によっては行数が変わる。変化量は文章の内容で動く（かなが多いほど大きい）ため、
実際に使う文面で測るのが望ましい。

調整ツールにこの測定を組み込んである。「プロポーショナル化の比較」の見本が 0.00 と 1.00 を
上下に並べ、**各行に描画された幅を em と比率で表示する**。サンプル欄の文面を差し替えれば、
その文についての変化量がその場で出る。

### 目で確かめる

同じ見本で、数値の隣に実際の組みが出ている。0.00 と 1.00 が上下に並ぶので、切り替えて
記憶で比べる必要はない。

見るべきは3点。

1. **漢字かな混じり文のリズム** — 漢字は `palt` の対象外で全角のまま、かなだけが詰まる。
   漢字 1000 に対し `あ` 971 / `ア` 931 なので、混じり文では最大 7% の幅の揺れが出る。
   本文サイズ（16px）で、かなが痩せて見えたり字間が不揃いに見えたりしないか
2. **カタカナが続く箇所** — `ア` は −69 と、ひらがな（`あ` −29）の倍以上詰まる。カタカナ語
   の連続で詰まりすぎが出ないか
3. **素の Noto Sans JP との比較** — 「締まった」と感じるか「痩せた」と感じるか

なお既定のサンプル文は和欧混植用のため、1と2の判断には向かない。サンプル欄を漢字かな
混じりの本文やカタカナ語の多い文に差し替えて見る。

### 選んだ値は設定に保存する

調整ツールのプリセットは **0.00 と 1.00 の2つ**。実質2択であり連続的に動かす意味がない
ため、スライダーにはしない。選んだ値は他の設計値と一緒に `config/tuning.json` に保存され、
そのままビルドに使われる。

## 8. M2 で決めること

| # | 項目 | 判断の仕方 |
| - | ---- | ---------- |
| 1 | **かなをプロポーショナル化するか**（1.0 / 0.0） | 字送りの変化量を測り、目視で確認（→ 7） |
| 2 | **全角英数をプロポーショナル化するか**（1.0 / 0.0） | 同上。かなと別に決められる |
| 3 | 「符号位置を持たないグリフ」を分類できるようにするか | → 6 の既知の限界 |
| 4 | 全角記号（`￥` など）を全角英数と同じ扱いにするか | 同上 |

1と2は調整ツールで選び、`config/tuning.json` に保存される（→ [tuner.md](tuner.md)）。
3と4は実装の変更を伴うため、影響が問題になると判断した場合に着手する。
